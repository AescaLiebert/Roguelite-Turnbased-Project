## How to Use

0. Bootstrap once per project: fill `1_Inputs_Templates/project-context-brief.md`, then run `/bootstrap-project`.
1. Confirm `1_Inputs_Templates/GDD_Fighting_Allstar.md` and `1_Inputs_Templates/project-stack.md` are filled with real project context.
2. Start every task from `Docs/3_Outputs/Specs/{slug}-task-card.md`, using `1_Inputs_Templates/Task_Card_Template.md`.
3. Route the task with `2_System_Files/Agent_Prompts/orchestrator-agent.md`.
4. Run one workflow: `/implement-feature`, `/fix-bug`, `/refactor`, `/code-review`, or `/report`.
5. Stop at human checkpoints for design feel, architecture, PR merge, team publishing, and risky automation.
6. After each session, write a DevLog entry from `1_Inputs_Templates/DevLog_Template.md` and save to `Docs/3_Outputs/DevLog/`.
7. Weekly, generate reports using `/report` or `.github/workflows/sprint-report.yml`.
8. Reference rules and policies from `0_User_Manual/RULES_AND_POLICY.md` and sync boundaries from `0_User_Manual/TEAM_SYNC_POLICY.md`.

## Context Policy

All normal project work gets design context from `1_Inputs_Templates/GDD_Fighting_Allstar.md` and its `@tag:` markers.

Bootstrap is the only exception: `1_Inputs_Templates/project-context-brief.md` is allowed to create the initial `1_Inputs_Templates/GDD_Fighting_Allstar.md` and `1_Inputs_Templates/project-stack.md`.

For Discord and Notion usage, follow `0_User_Manual/TEAM_SYNC_POLICY.md`: repo markdown is canonical, Notion is a planning/readability layer, and Discord is discussion/notification until converted into a tracked repo artifact.

## Token Policy

Agents should load only:

- `1_Inputs_Templates/project-stack.md`
- Current task card or current artifact (from `3_Outputs/Specs/`)
- Relevant GDD `@tag:` section
- Current agent prompt only (from `2_System_Files/Agent_Prompts/`)
- Relevant ADRs or affected source files only when needed (from `3_Outputs/ADRs/`)

Do not load all prompts, all docs, or the full repo by default.
