# Shared UI Toolkit screens

Gacha uses a vertical left banner list, a large selected promotional panel and docked Details/pull controls. Add configuration assets to the Gacha scene's `FrontEndController > Available Banners`; its existing default is included once. Each configuration supports optional poster, thumbnail and description. Selection changes the pool used by Details, selectors and paid draws. Rates/status labels can be removed in UI Builder: the banner binding skips missing optional elements. Current layout captures are in `Artifacts/GachaBannerNavigation`; only the KOF banner is authored, and long-list captures use unsaved layout samples.

Main Menu now uses a translucent shared header with separate live Diamond and Coin channels. Click either channel for its quick tooltip. **Backpack** is a separate Home action: Artifact, Material and Character Dupe tabs show inventory boxes with quantities and compact click/touch/keyboard tooltips. Artifacts are individual saved instances; Character Dupe lists separate fighter-bound token stacks earned from duplicate pulls after C5; each can only be used for its matching fighter. There is no persistent preview pane. Outside click, Close and Escape dismiss the overlay.

The current dungeon card reads the signed-in player's saved run. It shows the dungeon name, arena picture, current stage and difficulty, and switches the battle action to **Continue Dungeon**. No saved active run, or a completed/defeated/abandoned run, hides and disables the card. Continue uses the existing saved-run resume flow.

Choose Dungeon exposes five levels: **1 Easy, 2 Normal, 3 Hard, 4 Extreme, 5 Nightmare**. Reward samples are on the front Stage Info panel. The six-category overview shows Diamond, Coin, one Series Badge, phase and sub-phase upgrade materials, and a Flower from each eligible set in the stage artifact basket. Reward boxes are larger and sort by frame quality: Gold → Purple → Blue → Green → Grey. The basket label and Flower tooltip describe the two eligible sets; [DungeonArtifactBaskets.md](DungeonArtifactBaskets.md) lists every stage assignment. Fighter Preview still opens the eligible roster. Tooltips explain fixed currency payouts, material ranges and artifact chance. Gold frames mark both currencies; phase/sub-phase materials are Blue, series materials Purple; Common/Uncommon/R/SR/SSR artifacts are Grey/Green/Blue/Purple/Gold.

Shared references point to `Assets/Project/Resources/UI/ScreenShell.uss` and `AccountHeader.uxml` with their current GUIDs. This repairs the old references to `Assets/Project/UI` that caused UI Builder failures and default button/background styling across scenes. Keep a single shared source when moving assets.

**Fighting Allstar > Validate Main Menu and Backpack** renders real UI Toolkit documents at 1920×1080, 1280×720 and 768×1024. It covers hidden/active/finished dungeon cards, both currencies, shared styles/backgrounds, backpack tabs and instance counts, live inventory refresh, repeated open/close, Escape, tooltip bounds and the five reward previews. Evidence is written to `Artifacts/MainMenuRefactor`. The standalone runner is `Tests/CombatPresentation/RunMainMenuRefactorUiChecks.ps1`.

Select an owned fighter in **Main Menu > Characters**, then choose **Inspect Fighter** to open `CharacterHub.uxml`. The persistent account header remains visible. The hub follows the fighter-detail reference with a large portrait, four red/navy tabs, native skill cards and a gold ultimate panel. All fixed panels, buttons, stat cells, constellation nodes and equipment slots are authored in UXML/USS for editing in UI Builder. Existing fighter art, passive rules, skills, ranks and account progression populate the view. Full portrait art falls back to the fighter cutout, then the icon. Missing skill art uses labeled placeholders.

**Character Inventory** is an owned-fighter grid with search, rarity/attribute filters and rarity/name/level/constellation sorting. Click a grid card to open the inspector directly; the permanent preview and separate Inspect button have been removed. Back and Escape restore the filtered collection.

**Character Kit** has two panels: level and current basic stats with an all-stats Details popup, then three battle card visuals and a passive icon. Click an icon to inspect descriptions, rank/tier choices, status badges and keyword explanations using the same combat formatter as the battle inspector. **Upgrade** spends Coins to level up and displays matching phase/sub-phase/series item tiles for limit break. It persists real progression and applies owned-level stats to new dungeon formations and practice encounters. **Constellation** retains authored C0–C5 inspection; **Artifacts** now equips five pieces around the fighter, previews individual rolls and set effects, and opens the enhancement workshop. See [ArtifactImplementation.md](ArtifactImplementation.md) for rules, starting tuning values and UI assets.

See [CharacterProgression.md](CharacterProgression.md) for cap rules, starting economy values, editable per-fighter growth and material art direction. `Tests/CombatPresentation/RunCharacterUpgradeUiChecks.ps1` verifies progression transactions, persistence, growth scope, cap boundaries and native UI renders at 1920×1080, 1280×720 and 768×1024. Evidence is in `Artifacts/CharacterUpgrade`. Existing Character Inventory / Character Hub editor menu checks also cover direct grid navigation and the new cost layouts.

Main Menu, Gacha, Choose Dungeon, Dungeon Map and Character Loadout use native flex layout. The reference viewport is 1920 × 1080. `Fixed1920PanelSettings` uses Constant Pixel Size and scale 1; screen contents reflow rather than receive a whole-screen scaling transform. Compact and narrow classes handle smaller viewports. Background artwork crops to fill, while the dungeon graph retains spatial node coordinates inside a ScrollView.

All five documents instantiate `Resources/UI/AccountHeader.uxml`. Call `AccountHeaderView.Bind(root, backAction)` once when binding a document. Its Diamond balance follows `PlayerInventoryService.InventoryChanged`, with subscriptions removed when the document detaches. The same profile presentation and currency position appear on every screen. The current project has no account profile-name service, so the shared profile label remains Rookie.

Use `CharacterGridView.Populate(container, characters, select, enabled, badge, emptyMessage)` for character collections. It creates wrapping native cards through `CharacterIconView`, preserving the actual sprite, rarity frame, attribute and optional SUB badge. Gacha featured preview, results, rates/details, selector, dungeon previews and map enemy detail use this path. Loadout formation positions also use `CharacterIconView`. Decorative roster previews are removed.

Choose Dungeon has a vertical list of Open Circuit, KOF, Tekken, Soul Calibur and Genshin Impact. Open Circuit accepts all series; the other cards use `series.kof`, `series.tekken`, `series.soulcalibur` and `series.genshin-impact`. There is no global series dropdown. Phase/Sub-Phase live inside the selected dungeon Stage Filter and define an inclusive cutoff by ID: phase × 1000 + sub-phase × 100 + character index. Season2 / Begin (4 / 1) includes IDs 4100–4199, Season2 Launch, and every valid WIP, Pre-Release and Official-Release sub-phase. Future stages and malformed IDs are excluded. Preview, formation validation and route enemy generation share `DungeonProfile.Accepts`. Open Circuit saves its all-series cutoff as `dungeon.filter:*:phase:sub-phase`; series profiles retain their existing saved ID format. Legacy Women's runs remain loadable. Empty series display an empty preview and disable entry until sufficient runtime-ready content is authored.

Stage Info contains route, difficulty and reward information, with no character catalog. Dungeon Preview filters by series, cumulative phase/sub-phase and dungeon policy, sorts by descending rarity and then name, and only afterward overlays eligible characters that are unowned or not runtime ready. The overlay preserves the original sprite and shared frame/attribute artwork; excluded fighters never appear. Preview grids fit their panel without ScrollViews. Every ScrollView hides both scrollbars while retaining wheel/touch scrolling. Character Loadout places Active 1, Active 2, Active 3 and Reserve in a single horizontal formation above the scrolling owned-fighter grid, keeping search, assignment/clear, drag swapping and battle action. The legacy Canvas and raycaster are disabled; formation and battle validation continue through CharacterSelectionManager.

`ScreenShell.uss` centralizes the header, panels, buttons, grids and modals. `ScreenMotion.Show/Hide` control modal visibility; entrance opacity/translation and button hover/press use native USS transitions. The starting duration is 180 ms. Validate repeated clicks, dismissing a modal during entrance, pointer dragging and keyboard focus in Play Mode before tuning durations.

`Fighting Allstar > Validate Shared Screen Layouts` renders the real documents at 1920 × 1080, 1280 × 720 and 768 × 1024 using an isolated inventory. It checks viewport bounds, consistent header dimensions, live balance updates, CharacterIcon use, ScrollViews and formation visibility. Captures and results are written to `Artifacts/ScreenLayouts`. `Validate Dungeon Selection Layout` checks category/ownership restrictions, reward calculation, preview opening/closing and nine-row run generation. Preview fixtures do not persist an account, formation, run or scene.

### UI composition update

Fighter details expose Back in AccountHeader. Kit and Upgrade share four-stat rows; upgrade controls sit at the bottom. All item quantity/level tiles use a centered white footer. Upgrade requirements sort by frame quality. Dungeon previews show both eligible set Flowers in one fitted row. Stage Detail prioritizes larger enemy icons, team CC and possible loot; select an enemy to open an absolute popup with stats, passive and skills. Last Victory Rewards is removed from Stage Detail; the actual victory reward overlay remains. Landscape captures: `Artifacts/UiComposition`.
